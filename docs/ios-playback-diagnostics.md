# iOS 后台断流排查

原生播放器日志同时写入系统日志（分类 `Playback`）和 App 容器的
`Library/Caches/playback.log`。文件最大约 256 KiB，超限保留最新约 128 KiB；
系统可能清理缓存。日志不记录音频 URL、查询参数或歌名。

通过 Xcode → Window → Devices and Simulators → 选择设备 → Installed Apps →
选择 App → Download Container，显示包内容后查看 `AppData/Library/Caches/playback.log`。
日志包含 UTC 时间、曲目队列位置、播放秒数、播放意图、播放器状态、错误域/码和重试次数。

验证需安装新构建：

1. 正常播放后锁屏，保持后台超过此前出现故障的时长，确认继续播放/切歌。
2. 播放时断网，等待卡住，再恢复网络；确认保留进度恢复。
3. 断网期间回前台，确认会检查恢复；持续断网应进入有上限的指数退避，不高频刷请求。
4. 长时间断网后恢复网络，确认后续重试能重新加载；主动点击播放应重置退避。
5. 主动暂停、拔掉耳机、定时停止后恢复网络，确认不会自动开始播放。

明确加载/播放失败后，前 8 次分别在 0.3、0.5、1、1.5、2、2、3、3 秒后重试；随后以 4 秒为基准乘 1.5 退避，加入 ±20% 随机抖动，最终等待时间不超过 10 秒。每个周期只采样一次随机数。持续失败继续重试，主动暂停或定时停止会取消重试。
尚未明确失败的加载/缓冲每次保留 8 秒，避免在请求仍可恢复时过早重建。计时不包含系统请求自身耗时；iOS 挂起时计时器不会运行。
错误文案显示在播放栏上方的独立提示条内，最多两行，长 URL 或错误域不会挤压播放控件；完整错误仍保留在文本和 title 中。
正常推进进度会重置重试计数。恢复逻辑由原生计时器执行；iOS 挂起进程期间计时器不会运行，回前台重新检查。

使用 AVPlayerItem 的停滞、播放失败和错误日志通知：
https://developer.apple.com/documentation/avfoundation/avplayeritem/playbackstallednotification

## 消息与日志开销

- 前台进度消息最多每 0.5 秒一次，不携带队列、歌词和历史列表；队列变化或回前台时发送完整状态。
- 后台不推送 JS 事件；歌词、重试与定时停止继续在原生执行，回前台重新对账。
- 锁屏元数据在歌词/播放状态变化时立即更新，无变化时每 5 秒校准进度。
- 进度持久化从每 5 秒降至每 30 秒；暂停、切歌、进入后台等操作仍立即保存。
- 关闭 iOS Capacitor 桥接报文打印，保留原生故障、重试、恢复与生命周期日志。

## 控制台过滤

普通 `setup/load/foreground/background/pause` 事件默认只写 `playback.log`，不输出到控制台。
需要时在 Xcode Scheme 的环境变量添加 `ANYUN_VERBOSE_LOGS=1`，恢复这些调试输出。故障、重试和恢复继续输出，带 `[Playback]` 前缀。

WebKit、PointerUI、Accessibility、Fig 等系统组件输出不由 App 的日志开关控制。
在 Xcode 控制台按 Subsystem（App bundle ID）或 Category（`Playback`）过滤；也可搜索 `[Playback]`。
过滤只改变显示，不修复系统报告的问题；如果同时出现白屏、无声或崩溃，需结合现象继续排查。

## 锁屏标题歌词

原生恢复旧队列时，可能只有曲目摘要而没有歌词。构建前从 `src/lib/data.json` 生成 `static/native-lyrics.json`，随静态资源进入安装包。原生在恢复队列和接收配置时，按曲目 ID 补齐缺失/空歌词；已传入的非空歌词保持优先。
选择曲目时输出一次 `lyrics-ready lines=N`，用于确认原生是否已拿到歌词，不输出歌词内容或逐行日志。

## 原生恢复与前端对账

启动和回前台只读取原生状态，不回写整队列配置。前台读取不等待命令队列；旧响应及同序号重复消息均丢弃。配置在真正发送时才读取当前状态并切换 revision，排队期间继续接收原生恢复消息；未修改倍速的配置不再重新设置 AVPlayer.rate。
