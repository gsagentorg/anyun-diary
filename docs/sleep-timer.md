# 睡眠定时与音量渐弱

播放器的月亮按钮（窄屏在「更多功能」中）支持以下方式：

- **柔和渐隐**（默认）：分贝域 smoothstep，起步与收尾缓和。
- **匀速渐隐**：分贝线性下降。
- **轻声陪伴**：前 1/4 时间降到 -18 dB，剩余时间渐隐长尾。
- **先听后睡**：前 2/3 时间保持音量，最后 1/3 柔和渐隐。
- **长听快断**：开始几乎不降（中点约 -1.5 dB），随后逐渐加速下降，最后一刻从约 -14 dB 直接切断
  （分贝域三次曲线 + 硬切，没有 -60 dB 的微弱尾声）。
- **平稳后切**：前 82% 保持原音量，末端降到约 -12 dB，然后干脆切断。
- **阶梯渐弱**：0 / -6 / -12 / -18 dB 四级台阶，每级保持稳定，最后切断。
- **到时停止（不渐弱）**：保持音量，到时暂停。

渐弱方式附曲线示意；横轴是所选总时长，纵轴是相对分贝，并非线性音量倍率。定时运行时，曲线显示本次实际启用的方式，以移动圆点和竖虚线标记当前位置，并显示已过时长、百分比与当前阶段（如保持音量、渐弱中、轻声尾段）。

运行时切换下拉选择只修改下次启动的方式，当前曲线和标记仍对应正在执行的定时器，重新开始才切换。未启动、取消后或仅选择「播完本曲后停」时，不显示时间位置标记。

三个「快断」曲线（长听快断 / 平稳后切 / 阶梯渐弱）刻意不做微弱尾声：音量低到听不清却仍有声，反而让人费力去辨认；宁可长时间保持可听清的音量，再干脆切断。它们的 `sleepGain(mode, 1) === 0` 与其他曲线一致，区别只是**最后一刻仍是可听清的音量**，随后直接归零。

## 拖动渐弱进度

定时运行中，**整条竖虚线都是拖动命中区**（不只是那个圆点）：左右拖动即可把渐弱进度拨到任意位置，窗口总长不变、只平移起止时间；为防误触，最多只能拖到剩 1 分钟（要立刻停止请用「取消定时」）。位置圆点、竖虚线与曲线本身都随进度实时更新，键盘聚焦手柄后 `←` / `→` 每次 2%、`Shift+←/→` 每次 10%。

命中区几何在 `src/lib/sleep-curves.ts`：`SLEEP_TRACK_HALF_WIDTH = 13`（viewBox 单位，命中带整高 44、宽 26，手机上约 42×44 px），`sleepTrackHit()` / `sleepSeekProgress()` / `sleepSeekLimit()` 都是纯函数并有单元测试。

### iOS 上「拖不动」的成因与对策

1. **命中区只有一个点**：原实现只有 3.5 半径的圆点（约 16 px），手指很难正好落在上面 → 改为整条竖线。
2. **手势被判成滚动**：SVG 子元素上的 `touch-action` 在 Safari 支持不稳，系统把横拖当页面滚动并发 `pointercancel` → 轨道与 `<svg>` 上加 `touch-action:none`，并在拖动期间用**非被动** `touchmove` 兜底 `preventDefault()`（`Player.svelte` 的 `$effect`）。
3. **指针捕获丢失**：捕获设在会重渲染的子元素上，iOS 上可能失效（拖到一半停住）→ 捕获改设在 `<svg>` 根，并监听 `pointercancel` / `lostpointercapture`：取消时停在最后位置，不回弹、不报错。
4. **多指/次要指针**：记录活动 `pointerId`，忽略第二根手指与鼠标右键。

仍未覆盖：真机 iPhone 的 Safari/WKWebView 手势、系统媒体浮层弹出时的 `pointercancel` 时序。

## 行为约定

选择方式，再点时长或输入自定义分钟数开始。自定义范围为 1–600 分钟。

- 只记忆下次使用的渐弱方式，不持久化或自动恢复倒计时。
- 运行中的方式独立于下次选择。重新点时长才按新方式重新计时。
- 切歌、暂停、继续播放均不重新计时；倒计时按真实经过的时间运行。
- 取消时短暂平滑恢复原增益；到时先暂停，再恢复增益，避免响起一小段原音量。
- 播放器音量独立于系统音量。保留原有媒体音量，不改系统滑块。
- 「播完当前曲目后就停」保持原行为，不做渐弱。

## 实现与兼容性

优先使用原生 Web Audio：一个媒体元素只建立一条 `MediaElementAudioSourceNode → GainNode → destination` 音频链，跨曲复用。通过 `AudioParam.setValueCurveAtTime` 连续调节增益，不依赖每秒 JS 修改音量。分贝渐弱到 -60 dB，最后 2% 时间把尾声平滑收至零。

Web Audio 不可用时，验证媒体 `volume` 是否可写后采用兼容模式，并提示后台限制。连媒体音量也不可写时，显示「仅在到时停止」，不假装渐弱成功。

**网页不能保证系统挂起后的精确执行。** 即便提前安排了音频自动化，iOS/浏览器仍可能暂停 AudioContext、冻结页面或接管媒体。前台恢复/播放事件会按墙钟补算，过期立即停止。iPhone Safari 的真实锁屏、蓝牙耳机、长时间后台仍需真机验收，不可用桌面移动尺寸模拟替代。

睡眠测试覆盖所有曲线的单调/边界、预设存储、墙钟补算、切歌/暂停不重置、到时暂停与音量恢复顺序、取消/重启、定时器泄漏、原曲结束停止、降级与异步准备取消；另覆盖新增曲线的形状（慢起、分贝域加速、末端仍可听清后跳 0）、拖动命中区与进度换算、拖动时长窗口不变与「至少剩 1 分钟」的保护。

## 真机验收

1. 分别启动各预设，确认区别、曲线和当前运行状态。
2. 切歌/暂停/继续播放，确认增益不跳回、截止时间不变。
3. 取消并重新播放，确认恢复；到时停止后再播，确认正常音量。
4. Safari 锁屏/切后台后观察渐弱与停止；再回前台，确认不会继续播放已过期的定时器。
5. 测蓝牙耳机、系统打断恢复和横竖屏。
