# iOS 原生播放器验收

已将测试页替换为现有网页播放条控制原生播放服务。iOS 选播即使用 AVPlayer，无需点击额外测试按钮。Web 继续使用 HTMLAudioElement。

## 构建

```sh
npm ci
DEPLOY_TARGET=capacitor npm run build
npx cap sync ios
npx cap open ios
```

必须在 Xcode 重新运行到 iPhone，网页刷新或 cap sync 不会更新 Swift 程序。

## 已接入

- 网页播放条的播放、暂停、拖动、倍速，以及歌词点击定位。
- 原生持有完整队列，执行后台连续切歌、系统上一首/下一首、随机去重及历史回退。
- 原生音频会话、Now Playing 会话、锁屏控制、耳机断开暂停和系统允许后的中断恢复。
- 网页队列编辑同步到原生；快速操作串行提交并丢弃旧版本状态回调。
- 原生睡眠截止时间、五种渐弱模式、播完即停。暂停期间倒计时按墙钟推进；若进程被挂起，到期时不唤醒 App，之后恢复播放前先检查截止时间。
- 原生保存队列和进度；页面重载接回正在播放的服务；进程重启恢复暂停的队列与进度，不恢复睡眠倒计时。
- 原生加载与播放错误显示在播放条。原生状态是 iOS 播放状态来源，网页不另建音频实例。

## 真机步骤

1. 选一首歌，用普通播放条播放、暂停、拖动和切倍速，打开歌词后点击一句检查定位。
2. 连续快速选三首，应只播放最后选中的一首；队列删除/调序后曲目和进度不应错位。
3. 切换 App/锁屏，连续跨至少三首，检查自动切歌与系统上下首。
4. 暂停一两分钟后在系统内恢复；用另一个播放器抢占后再切回恢复；拔耳机应暂停。
5. 回前台检查标题、队列高亮、进度和歌词均跟随原生当前曲目。
6. 验证随机去重、上一首/下一首历史回退、睡眠渐弱和播完即停。
7. 重载页面仍保持当前原生播放；结束进程重开后恢复队列及进度并保持暂停。

自动验证：`npm test` 包括原有网页回归与桥接的命令顺序、旧回调过滤、后台切歌状态同步、前台对账、定位及错误恢复。iPhone 目标已编译通过；后台连续跨曲、睡眠渐弱及系统交互仍需按上述步骤真机验收。

## 睡眠与渐弱回归

恢复播放前先根据墙钟重算音量和截止时间，再启动 AVPlayer；到期先暂停，再恢复正常音量。睡眠设置使用独立 revision，队列/倍速同步不会清除“已停止”状态或重新启动已结束的定时器。原生计时器使用 common run-loop mode，拖动界面期间仍更新。取消后正常音量恢复；被中断后自动恢复同样先检查截止时间。

原生曲线与 Web 曲线的 1,000 点对照及状态检查（需 macOS / Swift）：

```sh
npx vite-node scripts/native-sleep-fixtures.mjs /tmp/anyun-sleep-fixtures.json
swiftc ios/App/App/NativeSleep.swift scripts/test-native-sleep.swift -o /tmp/anyun-native-sleep-test
/tmp/anyun-native-sleep-test /tmp/anyun-sleep-fixtures.json
```

真机建议分别测试：1 分钟柔和渐隐后锁屏等待停止；计时中暂停再恢复（音量应按已经过时间继续）；暂停超过截止时间后恢复（第一次恢复不应出声）；取消后恢复正常音量；播完即停不应进入下一首；计时中切歌/调速不应重置倒计时。
